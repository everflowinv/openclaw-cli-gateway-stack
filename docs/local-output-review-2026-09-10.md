# 本机 CLI 输出处理复查（2026-09-10）

根据桌面 LOCAL-AHEAD-OF-UPSTREAM.md 核查实际代码，采纳与模型列表无关的两项修复，并补上 Antigravity 的同类问题。

- Antigravity 工具错误/输出对象使用 JSON 保留字段；Error、循环引用、BigInt、toJSON 异常使用有长度限制的 inspect 兜底。工具参数也走同一处理函数，避免提前 JSON.stringify 抛错。
- Claude 和 Antigravity 的用量字段统一校验：数字字符串可用，负数、非数字、非有限值和不安全整数归零，小数取整数部分。Antigravity 原始用量与归一化用量使用相同规则。异常值归零是防止污染后续统计，不代表恢复了缺失的真实用量。
- 原有缓存计数口径和显式零值字段保持不变。没有证据表明省略零值字段会修复本机故障，因此没有照搬文档的字段省略建议。
- 文档所说的 effort 行为等价并不成立：忽略无效值与返回 400 不同。本机已有 resolveEffort 校验，保持原样。
- 未修改模型列表、OpenClaw 模型配置或定价，也没有添加文档中的 Opus 4.8。

验证：5 项纯函数测试、两个真实 HTTP / 合成 CLI 集成测试通过。集成测试确认错误对象字段出现在日志中、异常用量通过 HTTP 正确返回；原有队列超时、UTF-8 长度限制仍通过。本机服务空闲时分别重启，健康检查正常。

测试使用合成 CLI 输出，不消耗模型调用额度。共享实现位于 lib/cli-output.mjs；同步部署时须保留 lib/ 与两个网关目录的相对位置。
